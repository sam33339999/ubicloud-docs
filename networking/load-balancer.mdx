---
title: '負載平衡器'
---

Ubicloud 負載平衡器在多個虛擬機器（VM）之間分配流量，並確保您的應用程式的高可用性。負載平衡器在開放系統互連（OSI）模型的第 4 層運作。

Ubicloud 負載平衡器提供一個 DNS 名稱，這是客戶端的單一聯絡點。此 DNS 名稱對應到附加到負載平衡器的 VM 的公共 IPv4 和 IPv6 位址。傳入流量根據負載平衡演算法和健康探測在 VM 之間分配。

當流量到達負載平衡器的網路命名空間時，它透過評估負載平衡演算法、VM 健康狀態和連線狀態，將流量導向適當的 VM。此重新導向使用隧道模式的 IPSec 隧道，確保所有 VM 間流量都完全加密。

如果 VM 變得不健康，Ubicloud 負載平衡器會停止向該 VM 發送流量，直到它再次變得健康。這些健康探測和負載平衡器更新由外部且容錯的程序管理。這樣，即使一個或多個 VM 不可用，客戶端也可以繼續連線到他們的 VM。如果您從負載平衡器中移除 VM，Ubicloud 會更新 DNS 項目並保留負載平衡器節點，直到 TTL 過期。這確保了平滑的移除。

## 主要功能

- **DNS 整合：** 提供穩定的主機名稱和無縫連線，即使底層 IP 位址發生變化。
- **高可用性：** 透過在 Ubicloud VM 之間分配流量來提高可用性。
- **健康探測：** 監控負載平衡的 VM，並更新負載平衡器以僅將流量路由到健康的實例。
- **IPv4 / IPv6：** 支援多樣化的網路配置，包括 IPv6 的負載平衡。
- **安全性：** Ubicloud 負載平衡器在您的 Ubicloud 私有子網路內運作。因此，由負載平衡器管理的流量完全加密且安全。
- **多種演算法：** 支援輪詢和基於雜湊的負載平衡。
- **SSL 憑證：** 我們為負載平衡器主機名稱提供 ZeroSSL 憑證，您可以直接用於啟用 HTTPS 的 Web 應用程式。

## 入門

### 建立負載平衡器

**導航至負載平衡器：** 在儀表板上，從左側選單中選擇「Networking」選項。然後從上方標籤選擇「Load Balancers」

**建立新負載平衡器：** 點擊「+ New Load Balancer」按鈕。系統會提示您輸入以下欄位。填寫詳細資訊後，點擊「Create」。


- **Name：** 負載平衡器的名稱，也將用於主機名稱。
- **Private Subnet：** 選擇負載平衡器將在其中運作的私有子網路。請注意，來自不同私有子網路的 VM 不能混合在單個負載平衡器內。
- **Load Balancing Algorithm：** 在 round_robin 和 hash_based 演算法之間選擇。對於基於雜湊的負載平衡，使用以下欄位：
    - 來源 IP 位址
    - 來源連接埠號碼
    - 目的地 IP 位址
    - 目的地連接埠號碼
- **Load Balancer Port：** 配置負載平衡器將接受連線的連接埠（例如，連接埠 80）。
- **Application Port：** 後端 VM 提供連線的連接埠。
- **Health Check Endpoint：** 用於健康檢查的 HTTP 端點，例如 /up。確保您的應用程式向此 URL 發送回應代碼 200。

### 將 VM 附加到負載平衡器

**存取負載平衡器詳細資訊：** 從儀表板中，選擇「Networking」並選擇「Load Balancers」標籤。

您的私有子網路的概覽頁面提供子網路配置和資源的全面檢視。在這裡，您會找到：

**將 VM 附加到負載平衡器：** 在詳細的負載平衡器頁面底部，您會看到「Attached VMs」部分。您將點擊 VM 選擇器並選擇 VM，然後點擊右側的「Attach」按鈕。

### 從負載平衡器分離 VM

附加 VM 後，您可以從同一頁面將其分離，在「Attached VMs」部分，您需要點擊您想要分離的 VM 右側的「Detach」按鈕。

### SSL 憑證

Ubicloud 負載平衡器不支援 SSL 終止。但是，我們會自動為負載平衡器主機名稱生成公共 SSL 憑證。附加的 VM 可以使用以下命令輕鬆下載 `cert` 和 `key` 檔案：

```
sudo curl -f -L3 [FD00:0B1C:100D:5afe:CE::]/load-balancer/cert.pem
sudo curl -f -L3 [FD00:0B1C:100D:5afe:CE::]/load-balancer/key.pem
```
一旦您將這些檔案儲存在 VM 中，您就可以使用它們來提供啟用 HTTPS 的 Web 應用程式。

Ubicloud 每 2 到 3 個月自動更新憑證，並在同一端點提供新憑證。因此，建議建立一個腳本，下載新憑證並將其儲存在 VM 中作為 systemctl 服務。
