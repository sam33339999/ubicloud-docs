本指南向您展示如何下載、設定和使用 `ubi` 命令列程式。

### 下載

您可以從 [GitHub 上的 ubicloud/cli 發布頁面](https://github.com/ubicloud/cli/releases)下載最新版本的 `ubi`。我們為以下作業系統和平台提供 `ubi` 的下載：

* Linux：amd64/x86_64/x64、386/x86、arm64/aarch64
* macOS/Darwin：arm64（Apple silicon）、amd64（Intel）
* Windows：amd64/x86_64/x64、arm64

Linux/macOS/Windows 下載為 tar.gz 或 zip 檔案，每個檔案都包含一個名為 `ubi` 的單一檔案可執行檔，可以直接執行而無需安裝。

如果您是 MacOS 使用者，也可以透過執行以下命令使用 homebrew 安裝：
```
brew install ubicloud/cli/ubi
```

由於 `ubi` 是 Ubicloud 的一部分，它是開源的，並且[可供審查](https://github.com/ubicloud/ubicloud/blob/main/cli/ubi.go)。它是一個用 [Go](https://go.dev) 編寫的小程式，如果我們尚未為您的平台提供構建，您可以使用 GitHub 發布頁面上的原始碼下載自行構建 `ubi`。您也可以透過 [support@ubicloud.com](mailto:support@ubicloud.com) 聯繫我們，要求我們為您的作業系統和平台提供構建。

`ubi` 不會自動更新自己。它是一個簡單的程式，將您的命令傳輸到 Ubicloud。隨著 Ubicloud 新增對其他命令列功能的支援，`ubi` 可以自動利用它們。但是，在某些情況下，您可能需要更新版本的 `ubi` 才能利用其他命令列功能。在這種情況下，請使用上面的連結下載最新版本的 `ubi`。

### 設定個人存取權杖

為了運作，`ubi` 需要透過 `UBI_TOKEN` 環境變數提供個人存取權杖。如果您尚未為專案建立個人存取權杖，可以前往專案的 `Tokens` 頁面，然後點擊 `Create Token` 按鈕來建立：

![Create token screenshot](/quick-start/cli-1-screenshot.png)

這將建立一個個人存取權杖。點擊權杖標題下的剪貼簿圖示，將權杖複製到剪貼簿：

![View token screenshot](/quick-start/cli-2-screenshot.png)

您可以選擇如何儲存此存取權杖。如上所述，`ubi` 要求透過 `UBI_TOKEN` 環境變數提供它。如果您有密碼管理器或其他安全的秘密儲存庫，可以將權杖儲存在那裡。如果安全性不是您的主要關注點，您可以將存取權杖儲存在 shell 啟動檔案中，以便所有程式都可以使用它。

由於使用者可能希望以無數種方式儲存權杖，`ubi` 不提供特定權杖儲存的整合。您可以使用任何您想要的儲存方法，只要在執行 `ubi` 程式時存在 `UBI_TOKEN` 環境變數即可。

### 使用 `ubi`

如果您在不帶任何參數的情況下執行 `ubi`，它會顯示錯誤，然後顯示程式用法

```
$ ubi
! No subcommand provided

CLI to interact with Ubicloud

Usage:
    ubi command [command-options] ...

Examples:
    ubi vm list    # List virtual machines
    ubi help vm    # Get help for vm subcommand

Commands:
    ai         Manage AI features
    fw         Manage firewalls
    help       Get command help
    kc         Manage Kubernetes clusters
    lb         Manage load balancers
    pg         Manage PostgreSQL databases
    ps         Manage private subnets
    version    Display CLI program version
    vm         Manage virtual machines
```

`ubi` 會在錯誤前加上 `! ` 並將錯誤列印到 stderr 而不是 stdout。在這種情況下，您會收到錯誤，因為您在呼叫程式時沒有提供子命令。在這種情況下，`ubi` 會貼心地向您顯示可用的子命令。

其中一個子命令是 `help`。您可以使用 `ubi help` 來取得各種命令的用法資訊。例如，要查看 `ps` 子命令支援什麼，您可以執行 `ubi help ps`：

```
$ ubi help ps
Manage private subnets

Usage:
    ubi ps command [...]
    ubi ps (location/ps-name | ps-id) post-command [...]

Commands:
    list          List private subnets

Post Commands:
    connect       Connect a private subnet to another private subnet
    create        Create a private subnet
    destroy       Destroy a private subnet
    disconnect    Disconnect a private subnet from another private subnet
    show          Show details for a private subnet
```

這向您顯示使用 `ps` 子命令有兩種方式。一種方式有直接跟隨 `ps` 的子命令。在這種情況下，唯一支援的子命令是 `ps list`。那麼讓我們使用 `ubi help ps list`

```
$ ubi help ps list
List private subnets

Usage:
    ubi ps list [options]

Options:
    -f, --fields=fields              show specific fields (comma separated)
    -l, --location=location          only show private subnets in given location
    -N, --no-headers                 do not show headers

Allowed Option Values:
    Fields: location name id net4 net6
```

這向您顯示 `ps list` 命令的用法和選項。然後，您可以嘗試執行 `ubi ps list` 命令：

```
$ ubi ps list
location       name                   id                          net4             net6
eu-central-h1  default-eu-central-h1  psaw09mq9ea21pc5d30b5x1t16  172.31.34.64/26  fd9e:2db6:b05:bf0c::/64
```

您可以透過詢問來取得 `help` 子命令的說明：

```
$ ubi help help
Get command help

Usage:
    ubi help [options] [command [subcommand]]

Options:
    -r, --recursive                  also show documentation for all subcommands of command
    -u, --usage                      only show usage
```

這描述了 `-r`/`--recursive` 和 `-u`/`--usage` 選項。將它們結合使用以遞迴顯示子命令的用法非常有用：

某些命令類型適用於所有物件：

* `list`：顯示相同類型的多個物件的資訊子集
* `show`：顯示有關特定物件的詳細資訊
* `create`：建立物件
* `destroy`：銷毀物件（預設情況下在銷毀前要求確認）

其他命令是物件特定的。

### 執行程式

目前有 6 個執行程式的命令：

* `vm ssh`：透過 `ssh` 連接到虛擬機器
* `vm sftp`：透過 `sftp` 連接到虛擬機器
* `vm scp`：透過 `scp` 將檔案/目錄從本地電腦複製到虛擬機器或從虛擬機器複製到本地電腦
* `pg psql`：透過 `psql` 連接到 PostgreSQL 資料庫
* `pg pg_dump`：使用 `pg_dump` 傾印單一 PostgreSQL 資料庫
* `pg pg_dumpall`：使用 `pg_dumpall` 傾印整個 PostgreSQL 資料庫叢集

如果您想配置執行哪個程式，請設定適當的環境變數（例如，`ssh` 使用 `UBI_SSH`，`sftp` 使用 `UBI_SFTP`）。

### 命令列介面架構

上述說明應該是您使用 `ubi` 所需的全部內容。但是，如果您對 `ubi` 的運作方式以及為什麼以這種方式運作感興趣，可以閱讀本節。

`ubi` 與許多其他類似的命令列程式不同，因為它不解析它被呼叫的參數（`argv`）。它只是取得參數並將它們發送到 Ubicloud。Ubicloud 解析參數，確定要採取的操作，並將輸出返回給 `ubi`，後者為使用者顯示輸出（或在某些情況下，執行支援的程式或要求確認）。在 Ubicloud，我們將此稱為命令列介面設計的精簡客戶端方法。

以這種方式實作 `ubi` 的優點是，Ubicloud 可以隨時改進命令列介面以新增新功能，並讓 `ubi` 的使用者自動從這些功能中受益，而無需更新他們的程式。對於傳統的命令列程式，它們自己解析參數，新增新功能需要更新執行程式的每台機器才能使用這些功能。透過讓 `ubi` 將參數傳遞給 Ubicloud 而不解析它們，Ubicloud 將 Web 分發的優勢帶到命令列，以便所有使用者都可以立即從新功能中受益。

以這種方式實作 `ubi` 有幾個缺點：

* 所有命令都需要聯繫伺服器，因此即使取得 `help` 輸出也需要一些時間。
* 在執行程式時需要格外注意安全性，以便惡意伺服器不會導致執行 `ubi` 的機器上的遠端程式碼執行漏洞。

為了減輕精簡客戶端方法的潛在安全問題，`ubi` 進行以下檢查：

* 只能執行明確列入白名單的 6 個命令。
* 除非命令出現在傳遞給 `ubi` 的 `argv` 中，否則無法執行命令。
* 要執行的命令的參數：
  * 必須包含 `--` 以將參數與選項分開（除了 `pg_dumpall`，它不支援此功能）。
  * 只能包含一個不在傳遞給 `ubi` 的 `argv` 中的新參數。
    * 新參數必須在 `--` 之後（對於非 `pg_dumpall`）或必須以 `-d` 開頭（對於 `pg_dumpall`）

換句話說，Ubicloud 的命令列處理可以重新排列參數，並新增一個新參數，但該參數應該是執行程式的參數而不是選項。
