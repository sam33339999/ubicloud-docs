---
title: '透過 SSH 除錯工作流程'
---

除錯 GitHub Actions 工作流程可能是一個令人沮喪的經歷。我們都經歷過 - 您推送變更以修正工作流程，等待數分鐘，結果卻看到它再次失敗，並且日誌有限，無法完全解釋問題。這種試錯方法不僅耗時，而且效率低下。但是，如果有更好的方法可以即時除錯工作流程呢？

Ubicloud 推出了一個改變遊戲規則的解決方案：在工作流程執行期間可以透過 SSH 連線到託管的臨時 Ubicloud runners。使用 [ubicloud/ssh-runner](https://github.com/ubicloud/ssh-runner) action，您可以設定 SSH 存取並在工作流程執行時連線到 runner。不再需要猜測或無盡的提交週期。只需連線、即時除錯問題並繼續前進 - 全部在同一個工作流程執行中完成。

## 使用方法

要使用此功能，請將以下步驟作為第一步新增到您的工作流程中：

```yaml
- name: Setup SSH access
  uses: ubicloud/ssh-runner@v1
  with:
    public-ssh-key: ${{ secrets.SSH_PUBLIC_KEY }}
    wait-minutes: 30  # 可選，預設為 10 分鐘
```

就是這樣！此 action 將使用提供的公鑰啟用 SSH 存取。

當您執行此工作流程時，您將在日誌中看到以下輸出：

```
Waiting for 30 minutes to allow SSH access...

SSH Connection Information:
User:    runner
IPv4:    188.40.199.63
Command:
ssh runner@188.40.199.63
```

只需從日誌中複製 SSH 命令，打開您喜歡的終端機並連線。您將進入與 CI 作業相同的環境，讓您可以檢查檔案、執行命令並即時除錯問題。

請記住，每個 Ubicloud runner 都是臨時的。一旦作業完成後達到 `wait-minutes` 持續時間，VM 將被銷毀，連同其磁碟資料。

<Note>
  [ubicloud/ssh-runner](https://github.com/ubicloud/ssh-runner) action 是開源的。如果您遇到任何問題，歡迎查看、貢獻或開啟議題。
</Note>

您也可以僅為失敗的作業設定 SSH 存取：

```yaml
- name: Setup SSH access
  if: ${{ failure() }}
  uses: ubicloud/ssh-runner@v1
  with:
    public-ssh-key: ${{ secrets.SSH_PUBLIC_KEY }}
    wait-minutes: 30
```

<Warning>
  請安全地儲存您的私有 SSH 金鑰。短暫的除錯會話可以節省大量時間，但最佳實踐和安全準則始終適用。
</Warning>

## 結論

透過允許 SSH 存取您的 Ubicloud runners，您可以即時除錯 GitHub Actions 工作流程。這不僅節省時間，還能更全面地了解手邊的問題。告別盲目除錯和重複推送的日子。使用 Ubicloud 擁抱高效工作流程除錯的未來。

如需更多資訊，請造訪 [ubicloud/ssh-runner](https://github.com/ubicloud/ssh-runner) 儲存庫。
